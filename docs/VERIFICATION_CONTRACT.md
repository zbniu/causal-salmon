# Frozen offline verification exchange contract

Protocol: `f85fedf447c734d9d5e7a2cb630284fe18c7091c5cf653610adbc43ec8e7144c`.
This contract specifies serialization and orchestration only; planning.md remains the numerical authority. Main and independent programs must not import or copy each other's generation, statistics, tests, summaries or reference-analysis code. Common NumPy, configuration and this contract are allowed. Neither party sees the other's results before both initial selftests and code hashes have been registered.

## Invocation and storage

From the repository root: `python -m src.calibration.run --run-id calibration --workers 2` and independently `python -m verification.run --run-id calibration --workers 2`. Each defaults to all five candidates, A/B/C and all 1000 registered calibration seeds, in candidate order. `--resume` verifies immutable run identity before completing missing repetitions. `--selftest --seed 709000 --candidate K1 --world B` runs one complete diagnostic workload under purpose 4, outside formal calibration evidence. No development/formal seed is permitted here.

Main evidence is `results/calibration/<run-id>/main/`; independent evidence is its sibling `independent/`. A completed repetition is `<candidate>/<world>/<seed>/record.json` with `data.csv`, `students.csv.gz`, `truth.json`, `bootstrap.json`, `evidence.sha256.json` and a `COMPLETE` file containing the manifest SHA-256. Public-only reference inputs, reports and access audit live in `results/quality_checks/<run-id>/<implementation>/<candidate>/<world>/<seed>/<named|anonymized>/`. Both independently generate materials from the frozen protocol. Temporary incomplete directories are never counted as complete. Failed/invalidated runs are retained separately, with reasons.

Every JSON is UTF-8, LF, finite JSON numbers only (`allow_nan=False`), final newline. Unavailable and inapplicable numeric values are null with explicit status and reason. Gzip hidden tables are fully recoverable .17g CSVs. Compression metadata is not compared; recovered numerical values are compared. A unique hidden leakage probe is recorded for every case, outside the numerical comparison.

## Required repetition record

- `candidate` string; `world` A/B/C; `seed` integer; `purpose` integer; `csv_sha256` hex string; `x` integer vector in row order; `n`, `participants` integers; `applicants` integer for B/C, null for A.
- `T`, `identity_error`, `N` numbers.
- `primary`, `D1`, `D2`: result objects with `status` (`ok`, `unavailable`, `not_applicable`), `E`, `se`, `ci` (two numbers), `covered` boolean, `reason` string/null. Non-OK results have null unavailable values. D1/D2 are not applicable outside B.
- `bins`: null for A; otherwise `edges` six numbers, `treated` five integer counts, `control` five integer counts.
- D2 additionally contains `max_weight`, `ess`, `bootstrap_successes`, `bootstrap_failures` (zero-based indices); its original point estimate remains recorded even when a bootstrap makes its SE unavailable. `bootstrap.json` contains all 200 ordered objects with `index`, `status`, `E`, `reason`, and implementation-owned diagnostic details. Failure details must include data-level summaries and Newton iteration information where relevant. On successes details include iteration count.
- `invariants`: booleans `analytic_bounds`, `individual_effects`, `potential_bounds`, `csv_roundtrip`, `outcome_recomputed`, `counts`, `valid_csv`.
- `GEN`: keys `GEN-1` through `GEN-7`, each with `applicable` boolean, `passed` boolean/null, and ordered `reasons` list using clause-specific reasons. Reasons are diagnostic metadata; required GEN booleans must agree independently.
- `reference`: named/anonymized objects containing `input_hashes`, `method` (`random_difference`, `standardized_ols`, `insufficient_information`), `correct`, `format_valid`, `input_boundary_passed`, and `numeric` (`N`, `E`, `se`, `ci`). All these numerical and categorical fields are compared; implementation-specific access logs are audited separately.
- `details` may contain additional rank, leverage, fit and audit evidence. Extra details and raw prose are audited, not required to match byte-for-byte.

The comparator requires CSV SHA-256 and x exact, discrete/status/GEN/reference decisions exact, all common numerical fields (including every bootstrap estimate) satisfying abs(delta) <= 1e-8 * max(1, abs(main_value)), and null masks identical. Internal CAL-8 recomputation is bitwise within each implementation. Both programs independently write `summary.json` from all saved records: candidate/world metrics, D1/D2 metrics and conflicts, CAL-1..11, GEN counts/reasons, candidate status. Final-exam CAL-9 is explicitly deferred until parameter confirmation/material freeze; calibration template pairing is checked now. No missing diagnostic repetitions are discarded from aggregates.

## Boundaries and stop points

The public reference executable is self-contained and operates only on data.csv and STUDY_DESCRIPTION.md, choosing from pre-registered rules based on the public assignment paragraph, never backend world/seed/parameters. It is staged in a runtime-only directory and executed with a file-read whitelist, no network, sanitized environment, no parent project access. The hidden quality checker consumes its output separately. Reference input manifests, templates, reports, traces and isolation probes are retained for all repetitions. This is offline evidence, not tested-model output.

Independent selftest command: `python -m verification.selftest`. Main selftests: `python -m pytest tests`. After both pass, register both trees' SHA-256 fingerprints before formal execution. Keep source and input registrations immutable during each run. The offline workflow ends at the parameter confirmation request with a complete report and its hash; it never freezes a candidate or uses exam seeds.

## Required summary shape

`summary.json` has `candidates`, keyed by K1..K5. Each candidate contains `worlds` keyed A/B/C, each with `primary`, `D1`, `D2` metric objects and `support_passes` (null for A, integer for B/C). Every metric object has `status` (`ok`, `not_evaluable`, `not_applicable`), `count` integer, and numbers/null `bias`, `MCSE`, `relative_bias`, `coverage`, `precision_ratio`, `distinction_ratio`. For complete primary/diagnostic vectors use the same §6.4 formulas, including diagnostic precision and distinction ratios as calculation fields only (not new scientific metrics); diagnostic failure makes all aggregate numerical fields null. Do not present those extra diagnostic calculation fields as study outcomes. D1/D2 outside B are not_applicable, count0. Candidate `CAL` maps CAL-1..CAL-11 to booleans except CAL-9 null; `CAL9_status` is `deferred_final_material_freeze`. Candidate `diagnostic_conflicts` maps D1/D2 to objects with `status` (`ok`, `not_evaluable`), `conflict` boolean/null and `criteria` a 3-boolean list (null if not_evaluable) per §6.7. `state` is `passed`, `passed_review_required`, `failed`, or `invalid_implementation`. `GEN` maps world to GEN-1..GEN-7 counts: `applicable_count`, `passed_count`, `failed_count`, `reasons` (reason->count, explanatory and independently worded). Implementation-specific metadata may be additional; comparison targets the required metrics, states, CAL and GEN counts, not explanation wording.
